# GEO 진단 아키텍처

## 목표

하이스트비뇨기과를 포함한 한국 의료·지역 서비스 브랜드가 AI 검색에서 어떤 근거로 읽히고 인용될 수 있는지, 반복 측정 가능한 구조로 진단한다. 진단 점수는 코드가 계산하고, 언어 모델은 확정된 근거를 사람이 이해할 수 있는 문장으로 바꾸는 역할만 맡는다.

## 파이프라인

```text
URL + 브랜드 + 업종
        │
        ▼
공통 스냅샷 수집
  ├─ 온사이트: HTML / sitemap / robots / llms / JSON-LD
  └─ 오프사이트: 공공기관 / 학회 / 언론 / 커뮤니티 / 프로필
        │
        ▼
독립 분석
  ├─ Citability
  ├─ Authority
  ├─ Content E-E-A-T
  ├─ Technical
  └─ Schema
        │
        ▼
결정론적 가중합 → 개선 우선순위 → 마케팅 액션 → Markdown 리포트
```

## 점수 모델

현재 클라이언트 프로토타입의 가중치는 다음과 같다.

| 지표 | 가중치 | 대표 근거 |
|---|---:|---|
| AI 인용성 | 20% | 질문형 답변, FAQ, llms.txt, 내부 링크, 최신성 |
| 브랜드 권위 | 20% | 외부 권위 출처, 언론·커뮤니티, Person 연결, 자격 |
| 콘텐츠 E-E-A-T | 25% | 경험 사례, 자격·경력, 실명 저자, 외부 검증, 신뢰 페이지 |
| 기술적 인프라 | 20% | HTTPS, 본문 HTML, sitemap, robots, llms, 모바일 |
| 구조화 데이터 | 15% | Organization, FAQ, Person + sameAs |

영역 점수는 체크된 관찰 신호의 합으로 계산하고, 최종 GEO Score는 가중합한다. AI가 점수를 다시 쓰지 않도록 숫자와 서술을 데이터 구조 단계에서 분리한다.

## 실제 수집기 연결 규칙

1. 수집 시작 시각을 고정하고 하나의 snapshot ID를 만든다.
2. 모든 에이전트는 동일 snapshot을 읽는다.
3. 원본 HTML과 정제 텍스트를 모두 보관한다.
4. Trustworthiness는 footer가 제거된 텍스트가 아니라 raw HTML도 확인한다.
5. E-E-A-T는 다른 에이전트의 null 결과를 재사용하지 않고 원본에서 독립 판정한다.
6. 실명 저자와 `관리자`, `운영팀`, `admin` 같은 제너릭 저자를 구분한다.

## GitHub Pages의 한계와 확장 경로

정적 Pages는 브라우저에서 임의 사이트를 크롤링할 때 CORS와 실행시간 제한을 만난다. 운영형으로 전환할 때는 다음 중 하나가 필요하다.

- GitHub Actions가 주기적으로 수집하고 결과 JSON을 저장한다.
- 별도 API/Edge Function이 크롤링과 LLM 호출을 담당한다.
- 브라우저 BYOK는 사용자가 직접 선택한 AI 실측에만 사용하고, 서버에는 키를 전송하지 않는다.
