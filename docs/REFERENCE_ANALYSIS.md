# Growth Radar 레퍼런스 분석

## 문서의 성격

사용자가 제공한 붙여넣기 텍스트와 7장의 이미지에서 확인되는 내용은 구현 요구사항이 아니라, GEO 진단 시스템을 설계하기 위한 참고자료다. 따라서 원문 속 표현을 그대로 제품 사실로 확정하지 않고, 코드로 검증 가능한 원칙·데이터 구조·화면 요구사항으로 변환했다.

## 이미지별 분석

### Image 1 — GEO 분석 파이프라인

- 입력은 `URL + 브랜드명` 두 가지다.
- Phase 1은 온사이트·오프사이트 공통 컨텍스트를 수집한다.
- Phase 2는 AI 인용성, 브랜드 권위, 콘텐츠 E-E-A-T, 기술적 인프라, 구조화 데이터의 5개 영역을 병렬 분석한다.
- Phase 3은 점수 합산, 영역 간 교차 분석, 개선 우선순위, 최종 리포트, DB·대시보드 저장으로 이어진다.
- 구현 반영: `GEO 진단` 화면의 공통 입력, 5개 지표, 우선순위 큐와 Markdown 리포트 기능.

### Image 2 — GEO 대시보드 결과

- 총점·등급·설명 문장을 하나의 요약 카드로 보여준다.
- 영역별 카드에는 점수, 진행 바, 상세 보기 액션이 있다.
- AI 인용 실측은 별도의 상태 영역으로 취급하며, 인용률과 언급률을 혼합하지 않는다.
- 구현 반영: GEO Score 링, 등급 pill, 5개 영역 카드, `마케팅 분석`으로 이동하는 액션.

### Image 3 — 데이터 소스 분류

- 온사이트: HTML, sitemap.xml, robots.txt, llms.txt.
- 오프사이트: 위키백과, 언론 기사, 블로그·커뮤니티 후기.
- 온사이트는 자사 주장, 오프사이트는 외부 검증이라는 관점으로 분리한다.
- 구현 반영: 신호 체크 항목을 기술 인프라·구조화 데이터·브랜드 권위·콘텐츠로 분리하고, 향후 수집기에서 동일 스냅샷으로 공급할 수 있게 했다.

### Image 4 — 핵심 분석 영역

- AI 인용성: AI가 페이지 내용을 답변에 활용할 수 있는가.
- 브랜드 권위: 사이트 밖에서도 신뢰할 수 있는 기록이 확인되는가.
- 콘텐츠 E-E-A-T: 답변 재료로 믿을 근거가 있는가.
- 기술적 인프라: AI 봇이 손실 없이 읽을 수 있는가.
- 구조화 데이터: JSON-LD 등으로 의미가 명확히 표현되는가.
- 구현 반영: 점수 계산은 이 5개 지표를 독립적으로 계산하고, 최종 점수는 가중합으로 산출한다.

### Image 5 — E-E-A-T 근거 매트릭스

- Experience는 구체적 경험·수치·사례·1인칭 서술을 본다.
- Expertise는 실명·직함·자격·경력·프로필 연결을 본다.
- Authoritativeness는 외부 기관·학회·언론·sameAs 연결을 본다.
- Trustworthiness는 HTTPS, 수정일, 출처, 연락처, 개인정보·약관을 본다.
- 구현 반영: Experience와 Expertise를 하나의 점수 신호로 합치지 않고 별도 체크 항목으로 관리한다.

### Image 6 — 6가지 신뢰 기반 원칙

1. 메트릭 결정론: 측정·판정은 코드가 담당한다.
2. 관점 분리: Experience와 Expertise를 다르게 평가한다.
3. 메타데이터 신뢰: ‘작성자: 관리자’ 같은 기본값은 의미 있는 저자 신호가 아니다.
4. 검증 범위 제약: 자격은 About·팀 페이지까지, 경험은 해당 콘텐츠 단위로 확인한다.
5. 아키텍처 격리: 에이전트는 서로의 가공 결과가 아니라 동일 원본을 독립 분석한다.
6. 휴리스틱 제어: 업종이 불명확하면 성급하게 특정 업종 가중치를 강제하지 않는다.

### Image 7 — 운영 원칙

- 진단 점수와 LLM 서술을 분리한다.
- 제너릭 저자 표기는 통과시키지 않는다.
- 구조화 데이터가 실패해도 본문에 있는 근거까지 함께 지우지 않는다.
- 업종에 따라 E-E-A-T 가중치를 조정하되, 혼합 업종은 균등 프레임으로 보수적으로 처리한다.
- 구현 반영: 현재 정적 버전은 코드 기반 점수 계산을 우선 제공하며, 서버 수집기와 LLM 설명 계층은 후속 연결 지점으로 남겼다.

## 붙여넣기 텍스트의 핵심 주장과 구현 판단

| 참고 주장 | 제품에 반영한 판단 |
|---|---|
| AI 검색은 인용 여부가 핵심이다 | GEO 점수와 별도로 인용성 지표를 둔다. |
| 동일 사이트도 AI 평가가 흔들린다 | 동일 입력·동일 체크 신호에서 결정론적 점수를 계산한다. |
| 공통 스냅샷이 필요하다 | 입력 URL·브랜드·업종과 신호를 하나의 `geoState`로 저장한다. |
| E-E-A-T는 추상적이다 | 관찰 가능한 근거 항목으로 변환한다. |
| 의료·지역 서비스는 업종 맥락이 중요하다 | 기본 업종을 지역 의료 서비스로 두고, 커머스·미디어·SaaS 선택지를 둔다. |
| GEO만으로는 실무 액션이 부족하다 | 검색 의도·경쟁사 메시지·전환 액션을 `마케팅 분석` 화면으로 연결한다. |
| BYOK로 AI 실측을 붙일 수 있다 | 정적 Pages 환경에서는 사용자 브라우저 로컬 저장을 사용하고, 저장소에는 키를 넣지 않는다. |

## 범위 밖

- 이 레퍼런스만으로 실제 AI 검색 엔진의 비공개 인용 공식을 확정할 수 없다.
- 정적 GitHub Pages가 임의 사이트를 안정적으로 크롤링하거나 API 키를 서버 비밀처럼 보호할 수는 없다.
- 따라서 현재 버전의 점수는 분석 프레임과 UI 검증용이며, 실제 수집기·서버 프록시·LLM 호출은 별도 백엔드 작업이다.
